Статус: **ДЕЙСТВУЕТ** (кроме шрифта — см. п.1, ещё открыто). Логотип, палитра, рабочий
процесс и эталонный шаблон дизайна подтверждены владельцем 2026-08-25.
Написано 2026-08-24 по прямому запросу владельца: "прежде чем что-то формулировать в
документе — покажите на согласование".

## 0. Зачем этот документ

Посты B/D ушли в публикацию как чистая типографика на тёмном фоне — без фото, без
иерархии, без бренд-элемента. Это было признано неприемлемым. Этот документ — не
абстрактная теория, а конкретный список требований, которые CREATIVE_DIRECTOR обязан
проверить на КАЖДОМ посте, прежде чем он попадёт к QUALITY_CONTROLLER.

## 2. Обязательные правила для КАЖДОГО поста с картинкой (не рекомендация — требование)

1. **Никакого поста только с текстом на плоском фоне без причины.** Разрешено ТОЛЬКО
   для формата "статистична картка / чи знали ви" (см. `design_guidelines.md` п.6) — и
   даже там желателен фон-подложка с лёгким изображением, не голый цвет.
2. **Картинка должна тематически соответствовать содержанию поста** — не любое фото
   "для красоты", а конкретно то, что иллюстрирует именно эту тему (процесс стройки —
   фото стройплощадки/чертежей, рынок/локация — фото региона/готового объекта,
   lifestyle — фото виллы/бассейна).
3. **Источник картинки по приоритету** (см. `design_guidelines.md` п.1): реальное фото
   объекта > фото с сайта > подписанный концепт-рендер > типографский слайд (только для
   п.1 выше).
4. **Каждый carousel обязан иметь визуально отличающийся CTA-слайд** — не тот же
   шаблон, что контентные слайды.
5. **Логотип-значок на каждом посте**, не только текстовая подпись.

## 3. Видео и музыка — честное правило, не обещание невозможного

Статичная фото-карусель (свайп отдельных картинок) физически не имеет звука ни на
одной платформе — это не ограничение инструмента, так устроен формат.

**Правило с 2026-09-01**: карусель как формат не отменяется, она работает и остаётся
в плане — но не собирается больше как набор отдельных JPG для ручного свайпа. Вместо
этого карусель рендерится в видео: те же слайды, та же бренд-палитра из
`01_COMPANY/brand.md`, но кадры идут один за другим АВТОМАТИЧЕСКИ (слайд-шоу/Ken
Burns), с наложенной музыкой через ffmpeg. По факту это Reels/видео-carousel, а не
классический IG-carousel-пост. Пайплайн сборки — тот же, что уже использовался для
готовых Reels (`05_SOCIAL/Reels/Generated/`), источник кадров — карусельные макеты.
См. `00_SYSTEM/interaction_protocol.md`, раздел "Правило по каруселям".

- Музыка — либо встроенная библиотека платформы при ручной загрузке (без юридических
  рисков), либо подобранный royalty-free трек, вмонтированный при сборке видео
  (никогда чужой трек с авторским правом).

## 4. Инструменты — ПОДТВЕРЖДЁННЫЙ рабочий процесс с 2026-08-25

CREATIVE_DIRECTOR не рисует финальную картинку кодом — использует Canva
(`mcp__Canva__*`, подключена и активно используется). Реальный рабочий процесс,
проверенный на практике:

1. Взять реальное фото из папки Photodron (Google Drive, публичный доступ открыт —
   см. `06_PROJECTS/media_library.md`) — прямая ссылка формата
   `https://lh3.googleusercontent.com/d/{fileId}=w1600`.
2. `mcp__Canva__upload-asset-from-url` — Canva сама скачивает файл на своей стороне
   (её сервер, не наша песочница) — это то, что реально решило проблему "не могу
   посмотреть/скачать фото из Drive".
3. `mcp__Canva__generate-design` (design_type=instagram_post, asset_ids=[загруженное
   фото]) — подробный prompt с точными HEX из п.1, украинским текстом, правилом
   логотипа. Возвращает 3-4 кандидата.
4. Владелец выбирает кандидата → `create-design-from-candidate` → редактирование
   через `edit-design` (замена текста, размеры, позиции) по правкам владельца.
5. `export-design` для финального файла под публикацию.

**Эталонный шаблон** (подтверждён владельцем 2026-08-25, использовать как образец для
всех следующих постов): https://www.canva.com/d/FeRXg9N3tAmMZ_p — lifestyle-пост,
реальное фото из "красивый вид", бежевая плашка ~33% высоты кадра (не больше — правило
"текстовый блок компактный, не съедает фото"), рубрика на английском (LIFESTYLE COSTA
BLANCA — этот конкретный элемент по решению владельца на английском, остальной текст
поста — украинский), текст мобильно-читаемого размера (заголовок/подпись ≥24px на
1080px-канвасе, не 14-22px как в первых черновиках).

Adobe for creativity — всё ещё не подключена, не нужна, пока Canva закрывает задачу.

**Важно, проверено на практике**: `generate-design` иногда подставляет
AI-сгенерированный бессмысленный псевдо-текст вместо реального контента — CREATIVE_DIRECTOR
обязан прочитать весь текст на превью/через `read-design` и заменить любой
нечитаемый/не-украинский текст на утверждённый через `edit-design` ДО показа владельцу
как готового варианта.

## 5. "Максимально проработан для виральности" — конкретные критерии, не лозунг

- Первый слайд/первый кадр читается за 1 секунду — одна мысль, крупный текст.
- Формат/приём (не тема) подсмотрен у трендов недели (см. еженедельный Trend Scout) —
  но исполнение полностью оригинальное (жёсткое правило владельца, не нарушается).
- Единый визуальный стиль по всей ленте (цвета/логотип/шрифт из п.1) — узнаваемость
  важнее разового эффектного поста.
- Реальный, не постановочный кадр — аудитория отличает рендер от настоящего объекта,
  подписывать рендеры честно (см. `approved_claims.md`).

## 6a. Video Production Pipeline (Reels/TikTok) — интегрирован в существующую систему 2026-08-25

Не отдельная система, не новые агенты. По прямому указанию владельца: "Не создавать
новую систему из 15 агентов... Новый Video Production Pipeline должен быть
интегрирован в существующую архитектуру". Роль CREATIVE_DIRECTOR (16) расширена до
функции Video Director (выбор REAL/INTERNET/AI/IMAGE_TO_VIDEO по кадру, сохранение
архитектуры объекта, раскадровка) — это уже было в его зоне по `permissions.md`
("стандарт раскадровки Reels").

**Текущая фаза (2026-08-25, решение владельца)**: реального видео объектов почти нет
(2-3 неразобранных файла) → **режим avatar_mode = NONE, путь AI-генерации**, пока
владелец не наснимает реальное видео (тогда добавится оверлей Digital Avatar + текст
+ музыка вместо AI-генерации фона).

**Хранение**: `05_SOCIAL/Reels/{Projects,Generated,Approved,Rejected,Prompts,Reports}`
— создано 2026-08-25. Цель по словам владельца: копить библиотеку готовых
Reels, чтобы через 2-4 месяца часть публикаций закрывать повторным использованием уже
одобренных роликов, не генерировать каждый раз заново.

**Инструмент генерации фона — Runway** (через Zapier, `App227006CLIAPI`, см.
`00_SYSTEM/integrations.md`) — конкретных fal.ai/Kling/Seedance из первоначальной
спецификации в реестре нет, Runway закрывает ту же функцию. Статус: включён, НЕ
авторизован (нужен платный аккаунт владельца). Приоритет источника кадра по-прежнему
REAL → INTERNET → IMAGE_TO_VIDEO → AI_GENERATED — у нас есть реальные фото
("красивый вид"), значит для первого теста это `convert_image_to_video`
(реальное фото → видео), не генерация с нуля.

**Открытый технический вопрос**: `convert_image_to_video` отдаёт 5-10 сек за вызов,
монтаж нескольких сегментов в один файл — способ ещё не проверен на практике.

**Музыка — РЕШЕНО 2026-08-25.** Наложение музыки через Canva MCP невозможно (в
`edit-design` нет audio-операции — проверено). Локальный ffmpeg в облачном рабочем
окружении есть, но у самого окружения (и у моста к устройству владельца) нет доступа
к обычному интернету — заблокировано файрволом организации (подтверждено
диагностикой, включая попытку через Zapier code-action — тот тоже ограничен доменным
фильтром своего приложения). Единственный рабочий канал наружу — git-протокол к
github.com. Через него собрана библиотека из 15 CC0/Public Domain треков (источник
freepd.com, через агрегатор github.com/SoundSafari/CC0-1.0-Music) — разложена по 5
категориям настроения в `05_SOCIAL/Reels/Music/`, каталог с лицензией и источником —
`05_SOCIAL/Reels/Music/music_library_catalog.md`. Правило: CREATIVE_DIRECTOR берёт
трек по категории контента автоматически, без вопроса владельцу на каждый ролик.
Технически смешать трек с готовым видео (ffmpeg) можно только если файл видео тоже
физически доступен окружению — для видео, экспортированных из Canva (временная
подписанная ссылка), это отдельный нерешённый шаг: ссылку Canva тем же файрволом не
достать. Рабочие варианты: (а) наложить трек вручную в самом редакторе Canva (там
есть built-in Music-панель, просто не через MCP); (б) если нужен полностью
автоматический шаг — потребуется провести файл через мост к устройству/браузер, не
проверено на практике.

HeyGen (Digital Avatar) и ElevenLabs (голос) — найдены в реестре, пока не включены,
ждут фазы 2 (когда появится реальное видео).

**Музыка/Canva — ОБНОВЛЕНО 2026-08-25 (пересмотр решения выше).** Владелец
прямо отказался от Canva как инструмента компоновки видео: "у нас как такового
базового дизайна нет вообще... есть видео... на него накладываем озвучку,
музыку, текст. Какой ещё дизайн ты хочешь?" Дополнительный повод — Canva-
экспорт обрезал видео до 3 секунд независимо от длины исходника (баг: страница
дизайна унаследовала таймлайн формата "Story" из отброшенного первого варианта
`generate-design`, длительность страницы нигде не настраивается через
доступные операции `edit-design`/`resize-design`). Теперь пайплайн: исходное
видео (реальное или сгенерированное) → текстовый оверлей (прозрачный PNG,
координаты/цвета берутся из уже утверждённой владельцем Canva-вёрстки, но
рендерится отдельно, не через Canva-экспорт) → музыка по категории из
`Music/music_library_catalog.md` → всё сведено одним проходом `ffmpeg`
локально. Canva используется только как источник утверждённой вёрстки текста
(referência), не как инструмент вывода видео. Проверено на практике на Reel
#001 «ланусія 6» — 12.5 сек полной длины вместо 3-секундного бага.

**Музыка и озвучка — окончательное разделение правил (решение владельца
2026-08-25, после публикации Reel #001).** Это два независимых, отдельно
решаемых вопроса — предыдущие пункты этого раздела про музыку (ffmpeg-микс из
`Music/music_library_catalog.md`) остаются рабочим вариантом, но перестают
быть единственным/обязательным по умолчанию:

- **Музыка (фон)** — свободный выбор креативной команды, критерий один:
  дешевле/проще. По умолчанию — брать трек прямо из встроенной библиотеки
  площадки в момент загрузки видео в браузере (TikTok Sounds/Commercial Music
  Library, встроенный музыкальный пикер Reels у Facebook/Instagram) — это не
  требует ffmpeg-сведения заранее. Ручное вмонтирование трека
  (`Music/music_library_catalog.md`, CC0/CC BY) остаётся допустимым вариантом,
  когда это проще для конкретного ролика, но больше не единственный маршрут.
  Владелец: "по музыке без разницы... выбери сам, как проще, как дешевле — так
  и делаем".
- **Озвучка (voiceover)** — НЕ резервный вариант музыки и не альтернатива ей,
  а отдельный обязательный, постоянный маршрут производства. Для роликов без
  цифрового аватара ("просто красивая картинка") — обязательное наложение
  дублированного голоса владельца (клон голоса через навык `ai-voiceover`,
  ElevenLabs) поверх видео вручную, на этапе монтажа, до загрузки в браузер.
  Причина: не все будущие ролики будут с цифровым аватаром — часть будет идти
  только с озвучкой в голосе владельца, и для этого нужен рабочий маршрут
  наложения аудио на видео, который нельзя убирать даже после перехода на
  платформенную музыку. Владелец: "нам надо иметь маршрут для того, чтобы
  наложить эту озвучку на видео... это будем оставлять именно для озвучивания
  видео".

## 6b. Обязательный чек-лист публикации — финальная версия (2026-08-25, после полного прогона архитектуры)

Владелец: "сделай чек-лист, проверь его на основании нашей сегодняшней беседы,
чтобы мы к этому не возвращались... ты сам это проверяешь и даёшь мне уже
готовые проверенные результаты." Это самодостаточный список — FINAL_GATEKEEPER
(и ассистент) сверяются с ним сами, без возврата к владельцу по каждому пункту:

1. **Хештеги** — весь тег-бюджет площадки (IG до 5 / TikTok 5 / FB 1–3) на
   максимально релевантные теги: покупательское намерение (`#BuyVillaSpain` и
   т.п.) + гео (`#Benidorm`, при необходимости `#CostaBlanca`) + продукт/тип
   контента из готовых наборов `hashtag_system.md` §2-3. Тег собственного
   аккаунта в хештеги НЕ включается (решение владельца 2026-08-25, исправлено
   после первой версии правила — см. `hashtag_system.md` §0: такой тег не
   добавляет охвата, отнимает слот у тега, который реально приводит новую
   аудиторию через поиск). Никогда не пусто, никогда не один и тот же блок
   под все посты.
2. **Описание (caption)** — короткое, не "три простыни текста". Базовый
   шаблон (адаптировать 1-2 фразой под конкретный ролик, не копировать слово
   в слово): *"Skyline Benidorm — будівництво вілл під ключ у районі Коста-
   Бланка."* + одна короткая фраза по сути ролика. Строка атрибуции нужна
   ТОЛЬКО если реально использован трек с CC BY лицензией из `Music/
   music_library_catalog.md` (см. `Music/music_library_catalog.md`) — при
   музыке из встроенной библиотеки площадки или при чистой озвучке (см. §6a,
   "Музыка и озвучка") атрибуция не нужна.
3. **Контактная кнопка** — на практике ни у Instagram `publish_video`, ни у
   Facebook `page_video`, ни у TikTok/Buffer нет параметра "прикрепить кнопку"
   для органических публикаций (нативная кнопка-CTA — это функция платных
   Ads-кампаний, не обычного поста; проверено по схемам параметров всех трёх
   действий). Поэтому обязательный эквивалент: (a) CTA "Напишіть нам у
   WhatsApp" вшит прямо в кадр видео как текстовый оверлей — уже стандарт
   вёрстки; (b) в самом описании — явная строка с призывом и контактом
   (WhatsApp/профиль). Отдельно, разово (не на каждый пост) — владельцу стоит
   проверить в Meta Business Suite, что у Facebook-страницы "Skyline
   Benidorm" включена постоянная кнопка страницы "Отправить сообщение в
   WhatsApp" (это настройка уровня страницы, не поста; через доступный API
   прочитать/подтвердить её сейчас не удалось — permissions не отдают поле
   `call_to_action`).

4. **(только Facebook) Расшарить публикацию во все доступные группы** — Страница
   "Skyline Benidorm" уже добавлена владельцем в ряд групп, подобранных под
   целевую аудиторию (владелец ведёт членство в группах отдельно). Правило
   (владелец, 2026-08-25): **каждая** публикация на Facebook — Reels и обычный
   пост — в обязательном порядке дополнительно расшаривается во все доступные
   группы аккаунта. Не факультативно и не привязано ни к какому будущему
   условию — действует уже сейчас, для каждой публикации.
5. **Геолокация** — обязательна на Instagram и TikTok (Benidorm по умолчанию,
   см. `hashtag_system.md` §4a). На Facebook — искать поле заново при каждой
   публикации (в Reel #001 не найдено в использованном потоке — не факт, что
   его нет вообще); если найдено — то же значение.
6. **Музыка/звук** — либо уже вмонтирован(а) в файл заранее (музыка или
   озвучка), либо берётся из встроенной библиотеки площадки при загрузке — не
   оба сразу. Ролик "просто картинка" без музыки/озвучки/звука вообще не
   публикуется (см. §6a).
7. **TikTok — Disclose post content** — не фиксированное значение, а правило
   выбора (решение владельца 2026-08-25): включать для явно продающих роликов
   (цена/прямой CTA "купить"), не включать для lifestyle/процесса стройки —
   решать по каждому ролику отдельно.
8. **Файл** — шаг подготовки (`device_stage_files` с компьютера владельца +
   сверка md5 с Google Drive) пройден до захода в браузер — без этого не
   публиковать, см. `publishing_protocol_browser.md` шаг 0.
9. **Остальные поля формы** (Advanced Settings, AI-label — выкл. для реального
   контента, Comment/Reuse — вкл.) — осознанно просмотрены при публикации, не
   пропущены вслепую.

10. **Проверка звука по факту (добавлено 2026-08-26, после инцидента с
    TikTok)** — если для поста выбирается звук (п.6), редактор формы загрузки
    НЕ является источником истины: TikTok Studio (веб) может показывать трек
    как добавленный в превью формы, но не пришить его к финальной публикации
    фото-слайдшоу — воспроизведено на практике 26.08.2026, пост ушёл живым без
    звука несмотря на то, что в форме звук был выбран. Поэтому публикация со
    звуком не считается завершённой сразу после нажатия «Опубликовать».
    Обязательный шаг: открыть прямую ссылку на уже живой пост (не форму
    редактирования, не превью в форме загрузки) и подтвердить, что дорожка
    реально на нём висит. Если звука нет — считать публикацию дефектной и
    переделывать сразу, не откладывать. Дополнительная сложность: если пост
    помечен как коммерческий контент («Ваш бренд» / «Брендированный
    контент»), TikTok блокирует его редактирование в веб-версии — правка
    возможна только в мобильном приложении, значит переделка = удалить и
    опубликовать заново, а не поправить существующий пост.

Если хотя бы один из применимых пунктов не готов — публикация не выполняется,
возвращается на REVISE. После публикации — обязательно визуальное
подтверждение по прямой ссылке на живой пост (не тост, не превью формы
загрузки, не редактор) — включая звук, если он должен быть, — + запись в
`08_AUDIT` + смена статуса в файле сценария.

## 6d. Публикация видео — рабочий метод найден 2026-08-25

Прямая публикация через Zapier API (`publish_video`/`page_video`) — тупиковый
путь: локальные пути файла не долетают до соцсетей, обходные пути (публичная
ссылка на Drive, base64, hydrate-URL) блокируются платформой независимо от
разрешений владельца. Реально рабочий путь — публикация вручную через
веб-интерфейс, управляемый Claude in Chrome, в залогиненной сессии владельца.
Полная методичка с чек-листом полей по каждой площадке (включая геолокацию —
раньше пропускалась, это ошибка) и списком "чего не делать" —
`publishing_protocol_browser.md` в этой же папке. Обязательна к прочтению
перед следующей публикацией.
