# Правила публикации — Skyline Engineering

Владелец: SOCIAL_STRATEGIST / FINAL_GATEKEEPER. Первая сводная версия — 2026-08-24,
собрана маркетинг-директором из решений, разбросанных по `08_AUDIT/decisions/`,
`00_SYSTEM/integrations.md` и переписке. Единая точка правды по процессу публикации —
дальше сверяться сюда, а не искать по всей истории.

## 1. Язык и аудитория (см. AUD-002, TOV-005 — не пересматривать без владельца)

Приоритет покупателя: украиноязычная диаспора в Европе (главное) → русскоязычная
диаспора в Европе, явно НЕ Россия (вторично) → Казахстан/СНГ (низкий приоритет) →
англо-/испаноязычные покупатели Северной Европы (опционально, не приоритет).
Соответственно язык контента: украинский основной, русский вторичный, английский/
испанский не в приоритете.

## 2. CTA — правило для всех постов

Всегда WhatsApp (`https://wa.me/34643895440`), если посту вообще нужен явный CTA. Не
форма на сайте, не DM, не звонок.

## 3. Хештеги

Только по системе `05_CONTENT/hashtag_system.md`. Instagram — до 5, Facebook — 1-3,
TikTok — 5. Обязательно минимум 1 гео-тег (#CostaBlanca/#Benidorm/#Alicante). **Теги с
намерением купить готовую виллу (#BuyVillaSpain и т.п.) НЕ исключать** — см.
`08_AUDIT/decisions/2026-08-24_hashtag-purchase-intent-restored.md`: покупатели готовой
виллы — прямая целевая аудитория, кастом-стройка — альтернатива покупке, не отдельный
несвязанный сегмент.

## 4. Хостинг картинок

Google Drive → сделать конкретный файл/папку публичной (`role: reader, type: anyone`,
только с явного разрешения владельца в чате — это чувствительное действие) → использовать
URL строго в формате `https://lh3.googleusercontent.com/d/{fileId}=w1600`. Формат
`drive.google.com/uc?export=view` НЕ работает с Instagram API — проверено на практике.

## 5. Дизайн — см. отдельный файл `05_CONTENT/design_guidelines.md`

Кратко: реальное фото > фото с сайта > подписанный концепт-рендер > типографский слайд
(крайний случай, не стандарт по умолчанию).

## 6. Подтверждение перед публикацией — не отменяется никогда

Любая публикация (IG/FB/TikTok) требует явного "да" от владельца в чате на ИМЕННО эту
публикацию — готовый черновик показывается заранее. Наличие технической возможности
постить (подключённые API) не равно разрешению постить автоматически.

## 7. Дубли и последовательность

Перед публикацией — проверка на тематическое пересечение с постами, которые ещё не
вышли (не с уже опубликованными). Два похожих по теме поста подряд (например, две
статистические карточки про иностранных покупателей) — не выпускать один за другим,
разносить по времени.

## 8. Каданс

Не постить каждый день без остановки (RECOMMENDATION SOCIAL_STRATEGIST, не жёсткое
правило) — минимум 1 день паузы между плотными неделями контента, выходные слабее
реагируют у B2B/недвижимости.

## 9. Платная реклама

Meta Ads (Facebook/Instagram) исключены из плана на неопределённый срок — долг $678.78
на личном аккаунте владельца, Meta подтвердила отсутствие рассрочки. Не предлагать как
канал, пока владелец явно не передумает. Подробности:
`08_AUDIT/decisions/2026-08-24_no-paid-meta-ads-for-now.md`.

## 10. TikTok

Публикуется через Buffer→Zapier (не прямой коннектор). По формату — видео/Reels, НЕ
статичные фото-посты (это не ограничение инструмента, это как устроена платформа).
Статичные carousel-посты (как A/B/D) на TikTok физически не имеют смысла — только видео.

## 11. Музыка/аудио

Возможна ТОЛЬКО в видео-форматах (Reels/Stories) — у статичных фото-каруселей
(свайп отдельных JPG в ленте) звука нет ни у кого, это не ограничение доступа, это
механика платформы. Для видео — либо встроенная музыкальная библиотека платформы (при
ручной загрузке через приложение, без юридических рисков), либо royalty-free трек,
вмонтированный через ffmpeg при сборке видео здесь.

**Уточнение владельца (2026-09-01)**: карусель как формат не отменяется — карусели
работают и остаются в плане. Но собирается она не как набор статичных JPG для ручного
свайпа, а как видео: те же слайды (тот же контент, та же бренд-палитра), идущие один за
другим АВТОМАТИЧЕСКИ (слайд-шоу/Ken Burns), с наложенной музыкой через ffmpeg — по сути
Reels/видео-carousel. См. `00_SYSTEM/interaction_protocol.md`, раздел "Правило по
каруселям — авто-слайдшоу с музыкой, а не свайп".

## 12а. AI-аватар основателя — обязательная маркировка (решение владельца, 2026-09-03)

Причина: расследование застрявших на 1 просмотре постов TikTok Reel 1 и "Ланусія 6"
(см. `08_AUDIT/daily_log.xlsx`, запись 2026-09-03) — рабочая гипотеза: непомеченный
реалистичный AI-аватар/липсинк ловится автодетекцией TikTok и штрафуется потерей
тестового окна показов (1-й уровень их 4-уровневой системы: контент маркируется задним
числом, без явного удара по аккаунту, но ролик теряет критическое окно первых 30-90
минут). Решение владельца: аватар использовать и дальше — он экономит время на съёмку,
— но **с этого момента ВСЕГДА включать тумблер "Контент, сгенерированный ИИ" при
загрузке на TikTok**, когда в ролике используется AI-аватар/AI-липсинк основателя.
Тумблер доступен только на этапе загрузки (не редактируется постфактum) — не забыть
проверить его ДО публикации, не после.

Важно: разница между 1 просмотром у двух роликов и 200-800 у остальных — НЕ повод
менять формат "говорящая голова" сама по себе (владелец явно попросил не трогать
стратегию по этому поводу, 2026-09-03) — 1 просмотр объясняется отсутствием маркировки,
а не тем, что аудитория не любит формат с ведущим.

## 12б. Хук в первые 3 секунды (решение владельца, 2026-09-03)

Для всех новых сценариев, особенно плотных по цифрам/фактам (тарифы, сроки, список
городов и т.п.): первые 3 секунды — не начинать со статистики/сухих фактов. Нужен
крючок — вопрос, конфликт, неожиданное утверждение — который удерживает зрителя до
того, как пойдёт основной информационный блок. Источник: разбор алгоритма TikTok
показывает, что при отвале >50% зрителей в первые 3 секунды тестовый показ
останавливается независимо от качества остального ролика.

## 12в. AI-контент на Instagram/Meta — превентивное правило (владелец, 2026-09-03)

Meta официально объявила 2026-09-01 (за 2 дня до этой записи): снижение охвата для
"AI-generated profile", которые не раскрывают, что представляют синтетического
человека. Важная оговорка по факту-чеку (не путать с TikTok-правилом 12а): это
конкретно про аккаунты-персоны, а не про любой AI-контент, и для видео/аудио у Meta
пока нет подтверждённого автоматического наказания за охват (детекция там пока
работает только через добровольное раскрытие, в отличие от TikTok, где есть
документированная 4-уровневая система). Наш аккаунт — представляет реальную компанию
и реального человека, не синтетическую личность, так что это правило скорее
превентивное на будущее, чем объяснение текущей слабой статистики Reel 1 на Instagram
(см. 08_AUDIT/daily_log.xlsx, запись 2026-09-03 про реальные инсайты: 9 переглядів,
7 глядачів, 77.8% не читачі — тобто пост реально показали за межами підписників, це
не блокування як на TikTok, а провал на етапі утримання уваги/залучення).
Тем не менее: при загрузке видео с AI-аватаром на Instagram/FB, где такая опция
появится, — включать соответствующую маркировку, аналогично правилу 12а.

## 12. Порядок ревью перед публикацией (по системе SKYLINE_LOCAL)

CONTENT_WRITER → SOCIAL_CONTENT (платформенная адаптация) → QUALITY_CONTROLLER (факт/
бренд/SEO/язык/платформа/дубли) → FINAL_GATEKEEPER (APPROVE/REJECT/REVISE/HUMAN_REVIEW)
→ RISK_GATE (техническая проверка перед внешней записью) → публикация только после
явного "да" владельца (пункт 6).

## 13. Шеринг в группы после публикации — ОБЯЗАТЕЛЬНЫЙ ручной шаг на каждом посте (ужесточено 2026-09-13 по прямому запросу владельца)

Технически подтверждено 13.09.2026 и остаётся в силе: у Zapier для Facebook подключены только
5 действий уровня Страницы (`Create Page Post`, `Create Page Photo`, `Create Page Video`,
`Change Page Profile Photo`, `Page Post Insights`) — действия для публикации в Группы Facebook
отсутствуют в принципе, во всём реестре Zapier нет приложения "Facebook Groups". Это не пробел
в настройке, а ограничение платформы: Meta закрыла API для стороннего постинга в группы много
лет назад. **У Instagram и TikTok нет аналогичного понятия "группы" для бизнес-страницы/
аккаунта вообще** — делиться в них некуда, это применимо только к Facebook.

Поэтому владелец просил (13.09.2026): "при размещении любого поста автоматически делиться им
во всех доступных группах, везде, где это возможно". Технически "автоматически через API" не
реализуемо ни на одной из трёх площадок — ни один агент не может выполнить это сам. Что
реализуемо и с 13.09.2026 является ОБЯЗАТЕЛЬНЫМ (не опциональным, не "как было сделано один раз
для поста I") — шеринг в группы Facebook как жёсткий пункт чек-листа после КАЖДОЙ публикации на
странице, а не разовая практика:

1. Пост опубликован на странице Skyline Benidorm (после стандартного APPROVE + явного "да"
   владельца на конкретный пост, правило 6 — это условие публикации не отменяется).
2. Сразу после публикации на странице — владелец (или тот, у кого есть доступ к этим группам)
   вручную делится этим же постом во все доступные группы Facebook. Ни один агент не может
   выполнить этот шаг через API — технической возможности не существует физически.
3. AGT-03 обязан явно фиксировать статус шага 2 для каждого поста в отчёте/публикационном логе:
   `WAITING_ON_OWNER` (ещё не расшарено) или `DONE` (владелец подтвердил) — молчание об этом
   шаге и ссылка "не могу автоматизировать" без явного статуса больше не допускаются.
4. Если пост не расшарен в группы в разумный срок (тот же день) — это фиксируется в
   дашборде/отчёте как открытый пункт, а не теряется молча.
